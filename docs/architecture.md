# 구조와 제한

## 구성

IKView는 C++20으로 구성한 macOS 이미지·PDF 뷰어입니다. Qt Widgets가 창·메뉴·설정 UI를 담당하고, 직접 임베딩한 Qt Quick 창이 Metal 장면 그래프로 이미지를 표시합니다.

| 코드 | 역할 |
| --- | --- |
| `src/document.*` | 컬렉션, 정렬, 압축파일, 디코딩, 캐시, 애니메이션 |
| `src/nativeimage.*` | macOS ImageIO·CoreGraphics 디코딩과 PDF 페이지 렌더링 |
| `src/imagecanvas.*` | 표시 예산, 장면 그래프, 텍스처, 확대·이동·보기 효과 |
| `src/mainwindow.*` | 메뉴·목록·책갈피·탐색·사용자 작업 연결 |
| `src/exportdialog.*` | 변환 UI, PDF 묶기, 원본 보호, 비동기·원자적 저장 |
| `src/imagebackground.*` | 연결 영역 검색과 흰 배경 제거 |
| `src/preferencesdialog.*`, `src/shortcutmanager.*` | 설정, 사양별 캐시 프리셋, 단축키 편집 |
| `src/finder/`, `src/finderhandoff.*` | Finder 확장과 로컬 경로 전달 |
| `assets/integration/` | 설치기, 터미널 명령, Finder 상태 관리 |

## 응답성과 메모리

파일 스캔·정렬·디코딩·변환은 UI와 분리합니다. 요청마다 세대를 구분해 늦게 끝난 이전 결과가 현재 이미지를 바꾸지 않도록 합니다. 이미지는 앞뒤로 미리 읽고 LRU 캐시를 픽셀 비용 기준으로 제한합니다.

목록은 가상화하고 필요한 섬네일만 만듭니다. 큰 이미지의 표시 예산과 가시 영역을 구분하며 확대·회전·이동에 불필요한 전체 이미지 재생성을 줄입니다. 기본 전체 미리보기는 최대 4MP, 가시 영역 세부 이미지는 최대 8MP를 사용합니다. 1MP를 넘는 픽셀 가공은 제한된 비동기 작업에서 처리합니다.

캐시 예산은 앱 전체 메모리 사용량의 상한이 아닙니다. 원본 데이터, 디코딩 중 데이터, GPU 텍스처, 섬네일은 별도의 메모리를 사용합니다.

흰 배경 제거 미리보기는 최대 345,600픽셀로 제한하고 150ms 단일 타이머로 입력을 모읍니다. 동시에 하나의 미리보기만 계산하며 새 설정은 이전 계산을 취소합니다. 저장은 전체 해상도로 처리합니다.

## 파일 보호

이미지 변환은 원본과 같은 경로·심볼릭 링크·하드 링크를 거부합니다. 임시 파일에 기록한 뒤 마지막에 교체하며, 취소·실패·처리 중 원본 변경 시 기존 대상 파일을 보존합니다. PDF 페이지 순서 변경은 목록 행의 정체성을 유지하여 접근성 인터페이스를 안정적으로 관리합니다.

## 지원 범위

- 일반 입력은 파일당 256MiB, 디코딩당 128메가픽셀, 목록당 200,000개 한도를 사용합니다.
- 로컬 PDF는 4GiB까지 읽고 페이지를 144DPI·최대 16MP·8192픽셀로 렌더링합니다.
- 암호 PDF, 암호화·중첩 압축, 압축파일 내부 파일 수정은 제공하지 않습니다.
- PDF 변환은 현재 렌더링 이미지를 사용하며 벡터·텍스트를 보존하지 않습니다.
- 애니메이션·다중 페이지 파일 변환은 현재 또는 첫 프레임·페이지를 사용합니다. 원본 EXIF는 출력에 복사하지 않습니다.
- HEIC·RAW는 macOS ImageIO와 카메라 모델의 지원 범위에 따릅니다. HDR 출력과 전문 RAW 현상은 제공하지 않습니다.
- Windows 조건부 코드는 포함하지만 현재 Windows 빌드·실행은 검증하지 않았습니다.

성능 수치는 입력 형식·해상도·캐시·기기에 따라 달라집니다. 소프트웨어 렌더러 검사, 실제 Metal 검사, 디코딩 시간, 화면에 표시되기까지의 지연을 구분해 해석합니다.
